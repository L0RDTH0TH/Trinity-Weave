# Friction check (post-apply)

Before marking a `MINT-BACKLOG` item `done`, answer **both**:

1. Does this stub reduce imagined friction for **[persona]** (player / DM / both) in the moment of use?

2. Does this stub encode **one plot or structure as the product default** (e.g. “the game begins by…”, “first session teaches…”, one combat ending elevated as *the* authorship)?  
   If **yes** — re-scope to a structure menu / capability contract, demote the exemplar to an optional skin, or keep `in_dialogue`. Do **not** mark `done`.

Judgment, not a machine veto. Capability contracts (e.g. suggest-without-lock) usually pass #2; single-skin story nouns often fail it.
