# L5 — `ux_world_generation`

## What it is

A durable **world container** whose **initial form is DM-created**. The table can shape it; players do not author the first world. Creation uses a **world-generation wizard with previews**: tone-aware config families → cached/pre-existing noise or equivalent → preview → accept. Covers physical and settlement layers (terrain, cities, roads, trade routes, resources, water, foliage) plus region tags for monster-kind likelihood so a DM combat call can surface candidate encounter participants. The world outlives any single campaign; multiple campaigns and character sets attach to it. Background-driven adaptations may propose additions; **every world-hitting change is DM-retconnable**. Visible worlds list is first-class.

## Full vision

- Explicit world entity: identity, seed/provenance, world-tone defaults, region tags, campaign attach points
- DM-led wizard: create or attach → world-tone and shape families → preview → accept
- Structure menu: DM wizard-create | import canon bundle | attach to existing world
- Visible worlds list (same list idiom later for campaigns, characters)
- Background adaptations under DM gate + full retcon authority
- Monster-region tags feed combat candidate lists
- Exit into campaign-frame bootstrap or session prep — not forced character creation
- Intentional re-generation only for major structural change

## Early / PoC cut

One world identity, DM-led wizard (thin shape/tone families + single preview panel + accept), minimal worlds list. Scaffold-thin physical layer + a couple region tags if container + DM-initial + preview + attach + DM retcon are real. Stub adaptation/import contracts. Defer multi-world library, rich era authoring, full encounter-weight tables, mod packs.

## Out of scope

Campaign frame → `ux_dm_campaign_creation`. Character creation as world-create step → `ux_player_character_creation`. Players as initial world authors. Pure unconstrained multi-knob fresh-noise-every-time. In-session faction/weather/full sim continuity. Named adaptation sub-seam (DM gate + retcon is the rule).

## Alternatives not banned

- Nth campaign in a long-lived world vs first campaign in a newly wizard-created world
- Thin shape+preview accept vs deeper multi-step wizard on first create
- Import vs in-tool wizard-create only
- World empty of campaigns vs world carrying prior scars/legacies
- Directional world-tone × campaign-tone combinations
- Adaptation heavy vs light (still always DM-gated and retconnable)

## does_not_mandate

- one world equals exactly one campaign forever
- worldgen is only a Session 0 checkbox with no persistent container
- players author the first world
- world create forces unconstrained multi-knob fresh-noise every time
- world creation's default next step is player character creation
