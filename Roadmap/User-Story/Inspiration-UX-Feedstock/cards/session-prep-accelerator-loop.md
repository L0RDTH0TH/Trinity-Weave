# Session prep loop — optional accelerator

**Job:** session prep is an **accelerator** that prevents moments of pause while the DM works the system in the background to produce the desired response. It queues potential patterned branches rooted in the table’s own history so live play can continue smoothly. It is **not** a required ritual and **not** a second game.

## Necessity

Explicitly **optional**. The living world continues to function and carry continuity with zero formal prep. Prep only makes high-signal responses faster and more coherent when the DM chooses to use it.

## Branching & queuing model

1. DM marks a primary starter or current arc (e.g., retrieve X, clear Z).
2. From the history of play and the end-state of that arc, the system surfaces potential continuing threads.
3. Threads are **distilled** (not exhaustively mapped) into a small number of distinct patterned branches, each able to take different flavor/skins.
4. DM selects which branch(es) to queue or trigger.
5. System attempts to draft growth from within the table’s history; DM can always write or override manually above the table.

## Visibility

Primarily **DM-facing** workbench.

Session recaps (when used) are generated from **player notes/logs** rather than DM notes. This prevents bleed of non-player-facing information and keeps the recap personalized to the party/player experience.

## Stable / between-session surfaces

Surfaces that do not require constant in-play manipulation (e.g., economy that can remain stable for weeks of adventure time, certain institutional weather, longer-term ecological shifts) are managed in the prep loop.

Significant changes to these surfaces belong here and may require **regen**. Real-time in-world adjustment remains possible but is the exception for large shifts.

## Live hand-off

Warm entry into the table: queued branches, current pressures, active agents, relevant floated knowledge, and location state ready so play does not stall while the DM improvises cold.

## Post-session capture

Outcomes, new residue, and state changes flow back into history so the next prep cycle has fresh ground from which to grow patterned branches.

## Relation to locked surfaces

Consumes state from (and must be able to surface) Backgrounds residual pressure, Conditions (especially transformative and lingering), monster vacuum and cohesion, trap residue, hireling loyalty/staffing, treasure heat and DM flags, pantheon institutional weather, BBEG apex nodes, structures and player holdings, capacity expansions, and living-world continuity systems.

## Refuse (required)

- Heavy mandatory prep ritual
- Exhaustive “map every possible path” simulation
- Prep mode that feels like playing a second game
- Recaps that leak DM-only information
- Treating prep as the only way the world stays coherent
- Cold starts that force the DM to re-explain the entire world state from memory
